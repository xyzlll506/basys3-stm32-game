# 游戏原型协议 v1

游戏模式使用相同的三根 3.3 V TTL UART 线，115200 / 8N1、无流控。**FPGA 主动发送按键，STM32 回传角色状态。** 这是游戏模式协议，和 STM32 主动发送的 [UART 接线测试协议](protocol.md) 使用不同方向和回复长度。

## FPGA → STM32：按键请求，4 字节

| 偏移 | 含义 |
|---|---|
| 0 | `0xA5` |
| 1 | `seq`，8 位事务序号 |
| 2 | `buttons`，按键位图 |
| 3 | 前 3 字节按位 XOR |

按键 bit0 为左、bit1 为右、bit2 为跳跃、bit3 为重开；bit4～7 为 0。对应 Basys 3 的 L、R、U、D。C 键复位 FPGA。

左右同时按下时水平速度为 0。跳跃和重开由 STM32 检测上升沿，跳跃必须在着地时触发；持续按住不会自动连跳。

## STM32 → FPGA：状态回复，12 字节

| 偏移 | 含义 |
|---|---|
| 0 | `0x5A` |
| 1 | 原样返回请求 `seq` |
| 2、3 | 玩家左上角 x，uint16，小端 |
| 4、5 | 玩家左上角 y，uint16，小端 |
| 6 | flags |
| 7、8 | 死亡次数，uint16，小端 |
| 9、10 | 保留，固定为 0 |
| 11 | 前 11 字节按位 XOR |

flags bit0 表示着地，bit1 表示通关，bit2 表示这一步发生重生，其余位为 0。玩家矩形尺寸和关卡来自共享 [level.json](../game/level.json)。FPGA 只接收合法序号、校验、坐标与保留位的状态，并在帧边界交给绘图模块。

## 更新、超时与恢复

- FPGA 根据约 60 Hz 的显示帧周期发起请求，一次只等待一条回复；请求序号按 uint8 循环递增。
- STM32 对每条新的合法请求执行一次物理模拟步，时间单位为 1/60 秒。事务序号和按键都相同的重复请求只重发缓存，避免重复模拟；同序号却包含不同按键的请求会被拒绝。
- FPGA 的事务超时为 8 ms；超时或坏包不会更新显示状态，随后帧可继续请求。STM32 部分请求的字节间超时为 20 ms。
- 没有 UART 请求时 STM32 游戏不向前推进。此原型的游戏时间由收到的有效请求驱动，尚未实现独立时钟下的状态追赶。
- 连续约 1 秒没有有效回复时，FPGA 提示链路异常；屏幕仍保留最近合法状态。
- 此版本使用 XOR 作为入门校验，没有长度、转义、确认重传和完整 CRC。后续扩展地图、音效或较大状态包时，需要设计新版本。

单边复位后的序号、部分帧、错误校验及恢复需要通过仿真和实际双板测试；不要把原 UART 测试的 PASS 当成游戏协议已经在实体板上运行。
