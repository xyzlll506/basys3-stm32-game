# 初开发 UART 通信协议

当前协议用于验证 STM32 与 FPGA 的双向通信。它只有固定长度测试请求及回包，尚未定义游戏坐标、按键、地图或音效消息。

## 物理连接与串口参数

| 项目 | 约定 |
|---|---|
| 电平 | 3.3 V TTL UART |
| 波特率 | 115200 baud |
| 数据格式 | 8 数据位、无奇偶校验、1 停止位，8N1 |
| 流控 | 无 |
| STM32 串口 | USART6，PG14 TX / PG9 RX，AF8 |
| FPGA 串口 | JA1 RX / JA2 TX |
| 共地 | STM32 GND ↔ Basys 3 JA5 或 JA11 |

TX 接对端 RX，两块板各自 USB 供电。完整接头脚号见 [上手文档](getting-started.md)。这是 TTL 串口，不能接 RS-232 电平。

## 报文格式

每帧固定 4 字节，按表中从左到右发送，每字节 UART 数据位低位先行。

| 字节偏移 | STM32 → FPGA 请求 | FPGA → STM32 回复 |
|---|---|---|
| 0 | `0xA5`，请求头 | `0x5A`，回复头 |
| 1 | `seq`，8 位序号 | 原样返回请求 `seq` |
| 2 | `data`，8 位测试数据 | 原样返回请求 `data` |
| 3 | 前 3 字节的按位 XOR | 回复前 3 字节的按位 XOR |

例如，序号为 `0x01`、数据为 `0x23`：

```text
请求：A5 01 23 87
回复：5A 01 23 78
```

不存在转义字节。进入固定长度帧接收后，`seq`、`data` 和校验字节可以为任意 8 位值，包括 `0xA5`、`0x5A`。

当前 STM32 测试程序令 `data = seq`，首帧 `seq = 0`，每次尝试后递增并在 255 后回到 0。因此这一版 STM32 实际发出的请求校验字节始终为 `0xA5`；FPGA 仍按一般 XOR 规则验证，仿真也覆盖不同的数据值。

## STM32 行为

初始化完成后，每 500 ms 发起一次请求，同一时刻最多等待一次事务。发送超时上限为 20 ms；发送完成后，以 HAL 轮询方式接收完整 4 字节回复，总接收超时为 100 ms。

回复必须同时满足以下条件才算成功：回复头为 `0x5A`，序号与本次请求一致，数据与本次请求一致，并且 XOR 校验正确。程序不会重发失败请求，也不会持续扫描接收流来重新寻找回复帧头；下一轮请求前清除可能残留的接收字节或 UART 错误状态。

USART3 经 ST-LINK 虚拟串口向电脑输出文本日志，参数同为 115200/8N1。USART3 日志口与板间 USART6 数据口是两个独立串口。

| 日志 | 含义 |
|---|---|
| `PASS` | 收到完全匹配的合法回复 |
| `TIMEOUT` | 未在接收超时内得到完整回复 |
| `BAD` | 接收返回其他错误，或完整回复校验不通过 |
| `TX_ERROR` | 本次请求发送失败 |

蓝灯 PB7 每次尝试翻转；绿灯 PB0 每次成功翻转；红灯 PB14 在失败时亮、成功时灭。PB0 对应默认焊桥配置。

## FPGA 行为

空闲状态只将 `0xA5` 识别为请求头，随后按固定长度接收序号、数据和 XOR。校验通过则安排回复；校验失败则不回复。

- 字节间超时默认 20 ms，由 `RX_TIMEOUT_CLKS = CLK_HZ / 50` 定义；超时后丢弃未完成帧并回到等帧头状态。
- UART 停止位错误会清除当前接收帧，错误指示 LD2 翻转。
- 校验失败的第 4 字节若恰为 `0xA5`，会同时作为潜在下一帧的请求头；其他失败校验字节使接收器返回空闲。
- 请求头不包含长度或转义信息；如果字节丢失或错位，恢复依赖后续有效帧头、帧结束及超时，不能保证任意字节流即时恢复。
- 发送器可以发送一帧，同时缓存一帧待发回复。若请求超出此容量，多出的新回复会被丢弃，不重试。当前每 500 ms 一个请求远低于这个速率。

FPGA 收到合法请求后更新 LD15～LD8 并翻转 LD1。缓存溢出也不改变该合法请求指示，因此吞吐量测试应检查实际回复数量，不能只观察 LED。

## 后续扩展

游戏阶段需要明确消息类型、长度、坐标编码、更新频率以及丢包处理，再决定是否改用更强校验和中断或 DMA 接收。修改协议时应同时更新 STM32、FPGA、仿真及本文件；当前固定四字节协议不能直接承载完整游戏状态。
