# STM32 游戏原型

本目录是独立于 UART 接线测试的游戏固件。打开 `../MDK-ARM/nucleo_f413zh_game.uvprojx`，目标选择 `NUCLEO_F413ZH_GAME`。初次实物接线验证仍使用原来的 `nucleo_f413zh_uart.uvprojx`。

## 分工与配置

FPGA 每显示帧采集 Basys 3 板载按键，通过 USART6 发送输入；STM32 执行一帧游戏物理并回复人物坐标、状态和死亡次数。角色可左右移动、跳跃、在实心平台上落地、触碰危险区重生、到达出口胜利，以及手动重开。

使用原有 HSI 16 MHz、USART6 PG14 TX / PG9 RX、115200/8N1 和 USART3 ST-LINK 日志，不需要增加跳线或启用 UART 中断 / DMA。各侧必须使用配套的游戏 BIT / HEX；接线测试固件与游戏固件的通信角色和回复长度不同，不能混搭。

| Basys 3 按键 | 游戏输入 |
|---|---|
| btnL | 左移 |
| btnR | 右移 |
| btnU | 跳跃，按下边沿触发，空中不能二次跳 |
| btnD | 重开，按下边沿触发，死亡计数清零 |
| btnC | FPGA 复位 |

## 源码

- `Src/game_engine.c`：不依赖 HAL 的 Q8 定点游戏核心；水平速度 3 像素/帧，初始跳速 -10 像素/帧，重力 0.5 像素/帧²。
- `Src/game_protocol.c`：纯 C 接收状态机、重复序号处理和状态回包。
- `Src/game_link.c`：HAL 轮询串口接入、LED 和低频日志。
- `Src/main_game.c`：独立主程序与原有时钟配置。
- `tests/test_game.c`：真实游戏核心与协议的主机端回归测试。

关卡定义来自共享的 `../../game/generated/level.h`，由同一份关卡数据生成给 STM32 和 FPGA。不要只改单侧的生成文件。

## 协议

输入固定四字节：`A5 seq buttons xor`，校验是前三字节 XOR。`buttons` bit0 左、bit1 右、bit2 跳、bit3 重开，其他位必须为 0。

回复固定十二字节：

```text
5A seq x_lo x_hi y_lo y_hi flags deaths_lo deaths_hi 00 00 xor
```

末字节是前十一字节 XOR。坐标为人物左上角的无符号小端像素值；`flags` bit0 着地、bit1 胜利、bit2 本帧重生。重复的相同序号与输入重发缓存回复，不重复推进物理；相同序号但输入不同会被拒绝。任意新的有效序号都可继续，包括 FPGA 复位后的 0 和 255→0 回绕。半包间隔达到 20 ms 时丢弃；校验或高位输入错误不会推进游戏。

游戏按有效输入帧推进，断开输入时冻结。通信错误时跳过该输入帧，没有自动补算丢失的物理帧。本版适合初次演示，后续游戏可加入独立计时和更完善的会话同步。

## 观察与测试

- 蓝灯 PB7：每 500 ms 翻转，主循环心跳。
- 绿灯 PB0：收到有效输入后亮，超过 1 秒无输入熄灭；适用默认焊桥。
- 红灯 PB14：等待输入、接收错误或发送失败时亮；正常回复后灭。
- ST-LINK COM：115200/8N1，正常时约每秒输出一条 `GAME seq=... x=... y=... flags=... deaths=... tx=0`。日志表示 STM32 已接收并发送回复，不能单凭此日志认定 FPGA 已显示正确。

在仓库根目录重建：

```powershell
./stm32/build_game_keil.ps1
```

主机测试需要 Clang 或 GCC，编译的是生产使用的纯 C 核心和协议：

```powershell
python stm32/Game/run_tests.py
```

测试包括实心平台上下及侧面碰撞、跳跃边沿、空中禁二跳、边界、死亡 / 重开 / 胜利、协议错误恢复，以及从出生点只送按键的完整关卡通关。默认关卡已通过 179 帧、0 死亡的输入序列；因为平台底面为实心，起跳需要留出横向距离。
